# Daily for iPhone — Phase i1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Daily builds with EAS, installs on the user's iPhone 15 and runs every shared screen without crashing. Android-only features are hidden on iOS, and the Android app does not change.

**Architecture:** There is one pure `src/platform.ts` module: `features(os)` holds the flags and `storeName(os)` gives the store wording, and the screens read both. `modules/daily-native/index.ts` exports the real Kotlin module on Android and an inert JS stub on iOS, so the 11 importers keep working without edits that would crash. EAS (cloud macOS) builds the iOS app. `eas.json` carries the public `EXPO_PUBLIC_*` values, because `.env` is gitignored.

**Tech Stack:** Expo SDK 57, React Native 0.86, expo-router, Vitest, EAS Build (`eas-cli`), pnpm.

**Spec:** `docs/superpowers/specs/2026-10-09-daily-ios-design.md` (phase i1: "EAS iOS builds on the iPhone, shared screens, iOS layout").

## Global Constraints

- **Identity:**
  - bundle id `com.aaronalex.daily`
  - App Group `group.com.aaronalex.daily` (created by the user; not used until i2)
- **Devices:** iPhone only (`supportsTablet: false`). The test device is an iPhone 15 on iOS 17+.
- **Android must not regress:**
  - `pnpm test` stays green
  - `versionCode` stays 5
  - nothing under `android/` changes
  - after the change, an Android release build still runs on the Realme
- **Secrets:**
  - Never commit the OpenRouter key, the Supabase token or the Gmail password.
  - Only `EXPO_PUBLIC_*` values (all public keys) go into `eas.json`.
  - Never stage `.codex/` or `marketing/`.
- **Pushing:** the repo is public. Don't push; the user pushes with their own `!` commands.
- **Interactive steps are the user's:**
  - `eas login`
  - Apple ID sign-in
  - `eas device:create`
  - installing on the iPhone
- **Store wording:**
  - "Google Play" on Android, "App Store" on iOS.
  - This applies to every user-visible string that names the store.
- **Out of i1:** Screen Time, Live Activity, pushes, Apple sign-in, iOS RevenueCat products. On iOS, Today shows a calm placeholder in their place.

## Review Focus

1. **A screen calls a stub that returns a "permission missing" value and nags forever.** `hasUsageAccess()` is false on iOS, so every "Grant usage access" card or redirect must be gated by `features.usageAccess`, not only by the stub value. *Pinned by:* the Task 4 grep check and the on-device checklist.
2. **A background path imports a native call that throws on iOS.** minuteTask and runSync run headless; the stub must never throw, and async functions must resolve. *Pinned by:* the Task 2 test, which calls every stub member.
3. **The Android key leaks into an iOS RevenueCat init, or iOS gets no key.** RevenueCat rejects a Play key on iOS. With no iOS key, release builds must show "nothing to buy", not crash. *Pinned by:* the Task 3 tests.
4. **Wrong store wording on iOS** ("Cancel in Google Play"), which Apple review rejects. *Pinned by:* the Task 3 copy tests and the Task 4 grep check.
5. **The Android build changes by accident** (a new plugin, config or version change). *Pinned by:* the Task 6 Android build and `git diff --stat android/` being empty.

```ts
import { Platform } from 'react-native';

/** Features that exist only on Android. iOS equivalents arrive in later phases: Screen Time in i2, the Island in i3. */
export type Features = {
  usageAccess: boolean; sunnyChip: boolean; floatingSunny: boolean;
  keepRunningHelp: boolean; exactAlarms: boolean; googleSignIn: boolean;
};

export function features(os: string): Features {
  const a = os === 'android';
  return { usageAccess: a, sunnyChip: a, floatingSunny: a, keepRunningHelp: a, exactAlarms: a, googleSignIn: a };
}

export const storeName = (os: string) => (os === 'ios' ? 'App Store' : 'Google Play') as 'Google Play' | 'App Store';

export const FEATURES = features(Platform.OS);
export const STORE = storeName(Platform.OS);
```

If importing `react-native` breaks Vitest, check how the other tested modules avoid it (for example `vi.mock('react-native')` in setup). If nothing does, move the two `Platform` constants into `src/platformNow.ts` and keep `platform.ts` pure.
